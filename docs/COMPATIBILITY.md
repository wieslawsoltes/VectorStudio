# Vellum 2.0 compatibility and production boundaries

Vellum 2.0 is a working vector editor and reusable engine distribution. It does **not** implement every feature of CorelDRAW, reproduce its proprietary native writer, or establish print/enterprise certification. This is the support contract for the delivered code.

| Area | Implemented | Boundaries |
|---|---|---|
| Native CDR | A C++ adapter calls real libcdr/librevenge, enumerates all generated SVG pages, preserves their physical dimensions, sanitizes output and opens it in the editor. | Local native runtime only. A real CC0 single-page CDR fixture is tested. Version-wide and multipage CDR corpus qualification is incomplete. No CDR writer, native round trip, proprietary object semantics or claim of lossless conversion. |
| SVG | Static vector fragments preserve paths, nested groups/transforms, gradients, masks, clip paths, patterns, filters, embedded raster images and text paths. Import parses physical units separately from the viewBox. Fragments resize as vector objects. | Scripts, animation, foreignObject, external references and unsupported CSS are removed. Stylesheet elements are not retained; inline supported presentation styles are converted. “Explode SVG” uses the older Paper conversion subset and can lose masks/effects/text transforms; retain the original fragment for comparison. Inner SVG content is not individually editable until exploded. |
| ICC / CMYK | LittleCMS WASM parses a supplied CMYK ICC profile and performs real RGB↔CMYK transforms. Profiles, intent, bleed, ink limit, font faces and process values persist in the document. Solid process fills can be emitted directly as CMYK PDF operators, preserving pure K. | Normal canvas/SVG is an RGB preview. Full-page calibrated soft proof, gamut warnings, spot plates, overprint preview, trapping and ink separations UI are not implemented. Exact CMYK path export rejects unsupported effects and non-opaque groups instead of silently approximating them. |
| Print | Native Inkscape/Ghostscript pipeline generates a PDF/X-3:2002 candidate with embedded output ICC, trim/bleed boxes and a JSON structural report. Matching embedded fonts are shaped to outlines. Preflight reports missing font styles, overflow, image resolution, effects and ink coverage. | `externalCertification` is always false. No independent PDF/X validator, printer qualification, trapping, imposition, calibrated proofing or certified workflow. Transparency may flatten/rasterize. Named spot colors use process alternates. Review output with the print provider. |
| Mesh fill | Editable 2–8 point grid dimensions in the engine, movable points, per-point colors, bilinear patch interpolation, vector tessellation and a live inspector (2–5 grids). | This is a bilinear lattice, not a complete bicubic/Coons mesh implementation. No tangent-handle patch editing or native CDR mesh round trip. SVG output tessellates into clipped colored polygons. |
| Envelope | Editable four-corner bilinear envelope on vector curves, live corner editor, saved source geometry, curve conversion and envelope-aware bounds. | Nonlinear mapping of Bézier handles is an approximation to the continuously warped curve. Arbitrary cage/multisegment envelopes and exact nonlinear curve subdivision are not implemented. |
| Brushes | Pressure samples, uniform mouse pressure, variable-width ribbons, elliptical calligraphy nib angle/aspect and saved editable stroke parameters. | No image hoses, bristle simulation, textured/pattern brushes or comprehensive brush preset library. Pressure hardware and high-frequency coalesced events require device testing. |
| Typography | Persistent font faces/styles, native browser text, Unicode line breaking, paragraph frames/columns/insets, overflow threads across pages, direction/language, OpenType feature settings and HarfBuzz-shaped outline export. Arabic joining and Latin ligatures are tested with a real font. | No complete rich-text run editor, variable-font axis UI, color-font export, hyphenation dictionaries, vertical layout, footnotes, full script itemization/font fallback, or comprehensive text-on-path editor. Browser layout and outline output are not qualified across every font/script. Synthetic bold/italic is not silently treated as an embedded face. Uncompressed TTF/OTF are the qualified outline inputs; WOFF outline behavior is not qualified. |
| Nested documents | Nested groups, inherited locks/visibility, group compositing opacity, cycle validation, grouping/ungrouping, remapped copies and group administration. | Child coordinates remain in document space. There are no reusable symbols, master pages, external linked documents, per-layer blend modes or arbitrary group clipping. The objects docker remains a flat searchable view; nested groups have their own structure panel. |
| Multipage editing | All pages appear on one canvas and can be edited directly. Add, resize, rename, duplicate, delete, reorder, fit-all, page tabs, move-selection and cross-page drag are implemented. Exports support multiple pages. | Up to 100 pages; no facing-page spreads, master pages, page numbering engine, print imposition or drag-reordering page thumbnails. |
| Collaboration | Real Yjs maps/text/order sequences, WebSocket protocol, HTTP fallback, durable IndexedDB outbox, exact update acknowledgments, CAS persistence, local selective undo, comments, presence, revision recovery and authorization on every update. | Geometry arrays such as one path's point list remain atomic fields. Divergence during the initial connection is preserved as a recoverable conflict. The hosted D1 transport catches up through client pulses; a local room notification accelerates same-process peers. This is not a Durable Objects deployment or a demonstrated high-scale service. |
| Administration | Owner/editor/commenter/viewer permissions, session revocation, editing lock, revision-retention policy, audit records and audit export. Authenticated hosting identity or a trusted reverse proxy is required. | Administration is project-scoped. Organization tenants, SAML/OIDC login implementation, SCIM, directory sync, enterprise key management, regional residency, WORM audit storage and compliance certification are not implemented. No email invitations are sent. |
| Rendering | Retained SVG DOM, vector serialization, broad-phase spatial index and actual WebGPU texture compositing with SVG fallback. | The GPU path uses browser SVG rasterization followed by GPU compositing; it is not a native WGSL vector tessellator. No universal frame-rate guarantee, GPU/device matrix or large-document browser performance qualification. |

## Limits and file safety

Documents are limited to 8 MB of UTF-8 JSON, 20,000 objects and 100 pages. Font data counts toward the document limit. SVG input is limited to 4 MB. Native CDR input is limited to 8 MB. Native print accepts at most 20 SVG pages per job; prepared PDF limits are separately bounded. PNG export is capped at 64 million pixels. CRDT state is capped at 12 MB; automatic epoch compaction is not implemented.

SVG imports remove active content and external resources. Native parsers run as bounded child processes with time, address-space and file-size limits; these limits are not an OS security sandbox. Run native services behind authentication and isolate the host appropriately for untrusted file processing.

Document format `vellum` version 1 remains readable. Release 2 adds optional fields and the `svg` node type; earlier Vellum engines do not understand the new features. Native CDR compatibility follows libcdr's parser coverage, not a proprietary Corel SDK.
